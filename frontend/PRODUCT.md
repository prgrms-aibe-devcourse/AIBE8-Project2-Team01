# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

React + Vite (사용자 확인). 데스크톱과 모바일 웹을 하나의 반응형 화면으로 다룬다.
백엔드는 Spring Boot REST API(`/api/...`)이며 이 프론트엔드는 아직 API와 연결하지 않은 시안이다.

## Users

- 고객: 이사·청소·과외·레슨 같은 일상 서비스가 필요한 사람이다. 전문가를 일일이 찾아 문의하는 번거로움을 줄이고 싶어 한다. 서비스와 지역을 고르고 요청서를 작성한 뒤 받은 견적과 고수 정보를 비교하고 채팅 상담으로 이어간다.
- 고수: 전문 분야와 활동 지역에 맞는 고객을 만나고 싶어 한다. 프로필을 등록하고 매칭된 요청에 견적을 보내 상담으로 연결한다. 견적 발송과 채팅 시작에는 크레딧을 사용한다.

## Product Purpose

EFY(Experts for you)는 일상 서비스 고수와 고객을 견적 요청과 제안으로 연결하는 매칭 플랫폼이다.
메인 화면의 성공은 고객이 필요한 서비스를 발견하고 요청서 작성을 시작하는 것이다.
동시에 고수와 서비스를 둘러보며 관심을 키울 수 있어야 한다.

## Positioning

고객이 고수를 하나씩 찾아 연락하지 않는다.
요청서 한 장을 쓰면 조건(서비스 소분류·활동 지역)이 맞는 고수가 먼저 견적을 보낸다.

## Operating Context

- 카테고리: 대분류 11개(이사/청소, 설치/수리, 인테리어, 이벤트/뷰티, 과외, 외주, 취업/직무, 취미/자기계발, 자동차, 법률/금융, 기타)와 소분류 108개. 출처는 백엔드 `data.sql`.
- 지역: 시도(first_region) 16개와 시군구(second_region).
- 요청서: 소분류 1개 + 시군구 1개 + 공통 질문 답변(필요한 서비스, 희망 시기, 예산, 추가 요청).
- 견적 상태: SENT, REQUESTED 등. 요청서 상태: OPEN, MATCHED, CLOSED.
- 커뮤니티: 게시판 QUESTION(고수에게 묻다), TIP(고수 노하우), RECRUIT, PROMOTION.
- 찜(Bookmark): 회원이 고수 프로필을 찜한다.

## Capabilities and Constraints

- 공개 API: 카테고리·지역 조회, 고수 프로필 단건 조회, 공개 게시글 목록·상세.
- 없는 것(시안에서 실제 집계처럼 보이면 안 된다): 고수 목록·검색 API, 리뷰·별점 엔티티, 고수 프로필 등록일, 찜 수 공개 집계, 인기 순위 집계, 완료 건수 집계.
- 고수 프로필 필드: 닉네임, 한 줄 소개, 상세 설명, 경력 연수, 대표 서비스, 제공 서비스, 활동 지역(전국·시도 전체·시군구), 작업 사진.

## Brand Commitments

- 이름: EFY, 부제 Experts for you. 서비스 제공자를 "고수"라고 부른다.
- 로고: 청록과 파랑 두 고리가 맞물린 심볼과 EFY 글자. 원본은 백엔드 저장소 `docs/images/efy-logo.png`이고 프론트엔드는 `public/brand/`의 투명 PNG를 쓴다. 로고 색은 청록 #03948F와 파랑 #2F7FFD이다.
- 사용자가 직접 정한 문구: 히어로 제목 "Experts for you!", 설명 "요청서 한 장으로 여러 견적서를 받아보세요".
- 입체 아이콘과 고수 프로필 사진은 외부 이모지 세트가 아니라 프로젝트 전용 생성 이미지(`public/efy-assets/`)를 쓴다.
- 사용자가 지정한 참고 요소: 입체적인 서비스 카테고리 표현, 아래로 내리며 성격이 다른 고수·서비스 목록을 계속 발견하는 구성, 양옆 고정 여백, 넉넉한 여백, 사용 편의성 우선.

## Evidence on Hand

- 실제 데이터: 카테고리·지역·질문 시드(`data.sql`).
- 없는 것: 실제 고수 사진, 후기, 평점, 거래 건수, 언론 보도, 제휴사. 시안의 고수·게시글·수치·고수 캐릭터 이미지는 예시이며 화면에서 예시임을 밝힌다.

## Product Principles

1. 요청서 시작이 가장 짧은 경로에 있어야 한다.
2. 고객이 고수를 고르는 근거는 실제로 저장된 정보(경력·활동 지역·제공 서비스·작업 사진)에서 나온다.
3. 집계되지 않은 숫자를 신뢰 근거처럼 보여주지 않는다.
4. 고객과 고수 두 역할의 진입점을 모두 둔다. 화면의 중심은 고객이다.

## Accessibility & Inclusion

한국어 사용자 대상이다. WCAG 2.2 AA 대비와 키보드 조작을 기준으로 한다.
