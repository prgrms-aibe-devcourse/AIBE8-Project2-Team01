# 카테고리·지역 MariaDB 실제 API 검증

- 확인일: 2026-11-04 (한국 시간)
- 관련 작업: #174, #101, #110
- 대상: IntelliJ `EfyApplication-MariaDB`, `prod`, 로컬 8080 서버 → 클라우드타입 MariaDB `efy`
- 방식: 실제 HTTP 요청. H2 테스트나 MockMvc 결과가 아니다.
- 인증: 배포 시드 관리자 로그인. 비밀번호와 토큰은 기록에서 제외했다.
- 임시 이름 접두사: `check174-e1cf5f-`. 지역 코드는 기존 기준 데이터와 다른 99번대로 생성했다.

검증 전후 대분류 11개·소분류 108개·시도 16개·시군구 268개의 공개 API 응답이 동일했다. 기존 시드 이름·코드·ID·부모 관계를 변경하지 않았다. AUTO_INCREMENT는 임시 데이터를 만들고 삭제한 만큼 진행되며 임의로 되돌리지 않았다. 서버는 사용자가 이어서 사용할 수 있도록 실행 상태로 두었다.

## 요청 사례

- `POST /api/admin/first-categories`: `check174-e1cf5f-Race`와 `check174-e1cf5f-RACE`를 동시에 등록하여 201·409 확인
- `PUT /api/admin/second-categories/{생성된 임시 ID}`: 다른 부모에 있는 같은 이름 두 항목을 한 부모로 동시에 이동하여 200·409 확인. 대상 부모의 공개 조회에서 같은 이름이 한 개임을 확인
- `POST /api/admin/first-regions`와 `POST /api/admin/first-regions/{생성된 임시 ID}/second-regions`: 같은 새 코드로 동시 등록하여 201·409 확인
- `PUT /api/admin/first-regions/{생성된 임시 ID}`와 `PUT /api/admin/second-regions/{생성된 임시 ID}`: 같은 새 코드로 동시 수정하여 200·409 확인
- 카테고리·시군구의 부모를 존재하지 않는 ID로 수정하여 404를 받은 뒤 유효한 부모로 수정하여 200 확인

위 경로의 ID 표기는 기록 설명용이다. 이미 삭제한 임시 데이터이므로 복사용 실행 명령으로 사용하지 않는다.

## 검증의 한계

현재 단일 JVM의 HTTP 동작을 확인했다. 지역의 공통 `RegionLock`은 같은 JVM 안에서 요청을 직렬화한다. 여러 서버·레플리카 사이의 코드 중복 방지를 보장하는 결과가 아니므로 현재 구조에서는 서버를 한 개로 운영한다.

HTTP 요청의 출발을 맞췄지만 내부 트랜잭션의 특정 지점에서 충돌을 강제한 테스트는 아니다. 실패 후 정상 요청과 데이터 보존은 확인했으며 DB 내부의 롤백 과정을 직접 추적한 것은 아니다. name_key의 NOT NULL·UNIQUE 구조와 시드 정합성은 앞선 실제 DB 조회 결과이며 이번 API 응답만으로 DB 제약 전체를 재검증했다고 해석하지 않는다.

프론트 화면·HTTPS 쿠키·CORS·WebSocket 전송·결제·파일 업로드는 이번 범위에 포함하지 않았다.
