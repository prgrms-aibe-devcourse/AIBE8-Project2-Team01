# 의뢰 요청 시 견적서 검증·상태 전이 통합 테스트

- 도메인: 견적·매칭
- 결과: 통과
- 관련: #102, #103

## 확인 범위

- `QuoteService.requestQuote(customerId, quoteId)`: 채팅방 생성 쪽에서 호출하는 의뢰 요청 검증·상태 전이
- 견적 SENT → REQUESTED, 요청서 OPEN → MATCHED 전이
- 작성자, 이미 의뢰됨, 72시간 만료, 직접 취소, 없는 견적에 대한 거절
- `QuoteRequestTests` 8개 (`@SpringBootTest` + `@Transactional`, 테스트마다 롤백)

## 확인 결과

| # | 상황 | 기대 | 결과 |
| --- | --- | --- | --- |
| 1 | 유효한 SENT 견적에 의뢰 요청 | 견적 REQUESTED, 요청서 MATCHED | 통과 |
| 2 | 요청서 접수 기간(24시간) 지남, 견적은 72시간 이내 | 의뢰 요청 가능 | 통과 |
| 3 | 요청서가 이미 MATCHED | 요청서 상태 유지, 견적만 REQUESTED | 통과 |

| 8 | 없는 견적 ID | `QUOTE_NOT_FOUND_EXCEPTION` | 통과 |

```

```

테스트 데이터는 JdbcTemplate으로 직접 넣는다. 요청서는 이사(101)·강남구(39)로 만들어 expert1과 매칭되게 하고, `created_at`과 `sent_at`을 N시간 전으로 넣어 기간 조건을 만든다.

## 발견한 문제와 조치

- 첫 PR(#102)에서 테스트 파일을 add하지 않아 4줄짜리 빈 파일이 머지됐다. #103에서 테스트를 추가하고 파일명을 `QuoteRequestTests`로 정리했다. 이후 커밋 전에 `git diff --cached --stat`으로 줄 수를 확인한다.
- 자동 생성 ID를 하드코딩하면 시드 데이터에 따라 결과가 바뀐다. 테스트마다 데이터를 만들고 `max(id)`로 ID를 받도록 했다.
