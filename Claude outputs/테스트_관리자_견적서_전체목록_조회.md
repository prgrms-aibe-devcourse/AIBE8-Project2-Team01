# 관리자 견적서 전체 목록 조회 API 테스트

- 도메인: 견적·매칭
- 결과: 통과
- 관련: #158

## 확인 범위

- `GET /api/admin/quotes`: ADMIN 전용 견적서 전체 목록
- SENT·REQUESTED 모두 조회되는지, 72시간이 지난 SENT 견적이 스케줄러 삭제 전까지 포함되는지
- status 필터, 페이징, 정렬(id, sentAt, price, quoteStatus)
- 관리자가 아니거나 잘못된 파라미터일 때 거절
- 응답에 고수·고객·카테고리·지역 정보가 채워지는지

## 재현 명령과 응답

```bash
login() { curl -s -X POST "$BASE/api/public/auth/login" -H "Content-Type: application/json" \
  -d "{\"email\":\"$1\",\"password\":\"1234\"}" | tr -d '\n' | sed -E 's/.*"accessToken" *: *"([^"]+)".*/\1/'; }
A=$(login admin1@example.com); E=$(login expert1@example.com)

curl "$BASE/api/admin/quotes?pageSize=20" -H "Authorization: Bearer $A"
# → 200, totalElements 3
#   quoteId 1 (매칭고수 → 고객하나, 이사·강남구, 300000, SENT)
#   quoteId 3 (미매칭고수 → 고객하나, 이사·서초구, 280000, SENT)
#   quoteId 2 (매칭고수 → 고객둘, 이사·강남구, 200000, SENT, 11-01 발송)

curl "$BASE/api/admin/quotes?status=REQUESTED" -H "Authorization: Bearer $A"
# → 200, content [], totalElements 0

curl "$BASE/api/admin/quotes?pageNumber=2&pageSize=2" -H "Authorization: Bearer $A"
# → 200, quoteId 2, pageNumber 2, totalPages 2, lastPage true

curl "$BASE/api/admin/quotes?sortBy=price&sortOrder=asc" -H "Authorization: Bearer $A"
# → 200, quoteId 2(200000) → 3(280000) → 1(300000)

curl "$BASE/api/admin/quotes" -H "Authorization: Bearer $E"
# → 403 {"message": "접근 권한이 없습니다."}

curl "$BASE/api/admin/quotes?sortBy=description" -H "Authorization: Bearer $A"
# → 400 {"message": "페이지 번호, 크기 또는 정렬 조건이 올바르지 않습니다."}

curl "$BASE/api/admin/quotes?status=DONE" -H "Authorization: Bearer $A"
# → 400 {"message": "경로 또는 쿼리 값의 타입이 올바르지 않습니다."}
```

견적 2는 발송 후 72시간이 지났지만, 서버 기동 1분 안에 조회해서 스케줄러가 아직 삭제하지 않은 상태다. 관리자 목록은 유효기간 필터 없이 DB에 있는 견적을 그대로 보여 준다.

## 발견한 문제와 조치

- 처음 실행에서 모든 요청이 HTTP 000으로 실패했다. 코드 문제가 아니라 서버에 연결되지 않은 상태였다. 서버 기동과 `$BASE` 설정을 확인한 뒤 다시 실행해서 통과했다.
- `AdminQuoteResponse.java`가 빈 클래스였을 때 IntelliJ가 자동으로 add해서 `AM` 상태였다. 커밋 전에 다시 add하고 `git diff --cached --stat`으로 줄 수를 확인했다.

## 남은 확인

- REQUESTED 필터가 실제로 걸러 내는지: H2에서 `UPDATE quote SET quote_status = 'REQUESTED' WHERE id = 1;` 실행 후 status=REQUESTED 조회 시 견적 1만 나오는지 확인
- SQL 로그에서 목록 조회가 join select 1번으로 끝나는지 확인
